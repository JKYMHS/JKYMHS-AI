## 1. 개요

### 1.1 서비스
TourAPI(한국관광공사) 관광지·축제 데이터로 국내 여행 코스(당일–3박 4일)를 짜 주는 데스크톱 웹 서비스입니다. 코스는 여행의 일정안으로 저장하고, 확정한 일정안만 구글 캘린더에 단방향으로 올립니다.

### 1.2 AI 파트의 역할
- 서버가 후보를 고르고(무엇을 좋아할지), AI가 그 후보를 엮습니다(어떻게 엮을지).
- 모델 학습이나 파인튜닝은 하지 않습니다.
- AI 응답은 모두 Spring 서버를 거칩니다. AI 서버는 FE에 직접 노출하지 않습니다.

### 1.3 목표
| 목표 | 기준 |
|---|---|
| 제약을 지키는 코스 | 운영시간, 축제 기간, 꼭 포함 장소, 식사 시간, 페이스를 지킵니다 |
| 빠른 응답 | 통상 12초 이내, 최대 30초 |
| 실패해도 코스 제공 | AI가 실패하면 기본 추천 코스를 제공합니다. 오류는 인프라 장애일 때만 냅니다 |
| 개인정보 최소화 | 동의한 사용자의 행동 데이터만 쓰고, 외부 LLM에는 결제 계정으로만 보냅니다 |

| 용어 | 뜻 |
|---|---|
| 후보 | 추천 요청 조건에 맞춰 고른 장소 최대 40개. 코스는 이 안에서만 만듭니다 |

| 사전 검사 | 횟수를 차감하기 전에 요청이 가능한지 서버가 판정하는 단계 |

## 4. 사용자 흐름

```
① 추천 조건 입력 (지역, 기간, 시작 시각, 출발지, 동행, 실내 위주, 꼭 포함 장소)
② [코스 만들기] 클릭
③ 서버 사전 검사
     ├ 용량 초과 → "다음 날로 넘길까요?" 모달 → [하루 늘리기] / [이대로 짜기] → ②로
     ├ 꼭 포함 장소 방문 불가 → 사유와 비슷한 대체 장소 안내 → ①로
     └ 통과
④ 진행 화면 (후보 고르는 중 → 코스 짜는 중 → 운영시간 확인 중 → 이동 경로 찾는 중 → 식사 시간 넣는 중)
⑤ 결과 화면 (일차별 장소·순서·시각·체류 시간·추천 이유·이동 수단·라벨)
     ├ [다시 추천] → ④ → 필요하면 [이전 결과로] (한 단계)
     ├ 일차 수정: 장소 삭제·순서 변경, 식사 슬롯에 음식점 선택, 숙소 선택 → 시각·이동 재계산
     └ [일정안으로 저장] → 여행 상세 → [확정] → 구글 캘린더 업로드
```

## 5. 기능 요구사항

### 5.1 추천 입력 (FUNC-003-01 연계)

| 항목 | 규칙 | 상태 |
|---|---|---|
| 지역 | 시·도 하나와 그 안의 시·군·구 여러 개 | 기존 |
| 기간 | 당일–3박 4일. 과거 날짜는 선택할 수 없습니다 | 기존 |
| 첫날 시작 시각 | 09·10·11·13시. 기본값은 온보딩의 선호 시간대입니다 | 기존 |
| 출발지 | 주소 검색(카카오 로컬) 또는 현재 위치. 좌표는 저장하지 않습니다. 다시 추천이나 일차 수정 때는 FE가 출발지를 다시 보내고, 보내지 않으면 출발지 없이 짭니다(5.3) | 기존 + [신규] |
| 동행 | 혼자, 연인, 친구, 아이 동반(아이 나이 추가 질문), 부모님 | 기존 |
| 실내 위주로 짜기 | 기본 꺼짐. 켜면 실외를 빼지 않고 점수만 낮춥니다. 실내 후보가 부족하면 실외로 채우고 안내합니다 | 기존 |
| 꼭 포함 장소 | **최대 10곳.** 넘으면 "꼭 포함할 장소는 10개를 넘을 수 없어요" | [변경] (PRD v0.7은 5곳) |
| 꼭 포함 장소의 지역 | **같은 시·도** 안이면 선택하지 않은 시·군·구의 장소도 고를 수 있고, 그 시·군·구를 후보 지역에 자동으로 더합니다. **다른 시·도** 장소는 고를 수 없습니다(목록에서 비활성화). 요청이 들어오면 서버가 거절합니다 | [신규] |
| 페이스 넘기기 | 요청 필드 `allowOverPace`. 용량 초과 모달에서 [이대로 짜기]를 고르면 `true` | [변경] |

### 5.2 사전 검사 [신규]

코스 만들기를 누르면 서버가 먼저 요청이 가능한지 판정합니다. **FE는 용량을 계산하지 않고 서버 응답만 따릅니다.** [변경] 사전 검사에서 걸린 요청은 횟수를 차감하지 않습니다.

**용량 초과**
- 용량 = 여행 일수 × 페이스 상한(여유롭게 3, 알차게 5)에 동행 보정을 적용한 값입니다. 계산은 서버만 합니다.
- 꼭 포함 장소 수가 용량을 넘으면 "다음 날로 넘길까요?" 모달을 띄웁니다.
  - **[하루 늘리기]**: 종료일을 하루 늘려 다시 요청합니다. 이미 3박 4일이면 이 버튼을 보여 주지 않습니다(서버 응답 `canExtend`).
  - **[이대로 짜기]**: 기간을 유지하고 페이스를 무시한 채 모두 넣습니다(`allowOverPace: true`).

**꼭 포함 장소 방문 불가**

| 사유 | 안내 문구 (예시) |
|---|---|
| 삭제된 장소 | "○○은 더 이상 정보가 제공되지 않아요" |
| 축제 기간이 여행 기간과 겹치지 않음 | "○○은 여행 기간에 열리지 않아요 (축제 기간 MM.DD–MM.DD)" |
| 여행 기간 내내 휴무 | "○○은 여행 기간에 모두 휴무예요" |
| 운영 시간이 최소 체류 시간보다 짧음 | "○○은 운영 시간이 짧아 일정에 넣기 어려워요" |

- 사유마다 **비슷한 장소 최대 3곳**을 대체 후보로 함께 보여 줍니다.
- 운영시간을 알 수 없는 장소는 방문 불가로 판정하지 않습니다(5.4).

**후보 없음**
- 조건에 맞는 장소가 하나도 없으면 "조건에 맞는 장소를 찾지 못했어요. 지역이나 조건을 바꿔 보세요"를 안내합니다.

### 5.3 AI 코스 생성 (FUNC-003-02)

| 항목 | 규칙 | 상태 |
|---|---|---|
| 결과 내용 | 일차별 장소, 순서, 방문 시각, 체류 시간, 추천 이유(40자 이내), 이동 수단과 시간, 라벨 | 기존 + 이유 길이 [신규] |
| 추천 이유 | 장소 정보(분류, 태그, 설명)에 있는 내용만 씁니다. 가격, 할인, 영업시간, 주차, 예약 여부는 쓰지 않습니다. 규칙에 맞지 않으면 그 장소의 이유만 기본 문장으로 바꿉니다 | [신규] |
| 시각 계산 | 시각은 서버가 계산합니다. AI는 순서, 체류 시간, 식사 위치, 이유만 정합니다 | [확정] |
| 응답 시간 | 통상 12초 이내, 최대 30초 | [확정] |
| 진행 단계 | 후보 고르는 중 → 코스 짜는 중 → 운영시간 확인 중 → 이동 경로 찾는 중 → 식사 시간 넣는 중 | 기존 |
| 대기 한도 | FE는 2초 간격으로 상태를 확인하고, 60초가 지나도 끝나지 않으면 "코스를 만들지 못했어요. 다시 시도해 주세요"를 표시합니다. 이 경우 횟수는 차감되지 않습니다 | [신규] |
| 일정안 장소 수 | 1–30곳 | 기존 |
| 삭제된 콘텐츠 | 추천에서 제외합니다 | 기존 |
| 다일 여행의 출발점 | 2일차부터는 **전날 마지막 장소**에서 출발합니다. 숙소를 고르면 숙소에서 출발하도록 다시 계산합니다 | [신규] |
| 첫날 출발 | 출발지가 **가까우면**(선택한 시·도 안이고 후보 장소들의 중심에서 직선거리 30km 이내) 시작 시각에 출발지를 떠나 첫 장소까지의 이동을 일정에 넣습니다. **멀거나**(다른 시·도, 30km 초과) 출발지가 없으면 시작 시각에 첫 장소에서 시작하고 "출발지에서 ○○까지 오는 시간은 일정에 포함되지 않아요"를 표시합니다. 지역 간 이동(KTX, 고속버스 등)은 계산하지 않습니다 | [신규] |

**동행 유형 보정** (값은 설정으로 조정, Notion 명세와 대조 필요)

| 동행 | 보정 |
|---|---|
| 아이 동반 | 체류 시간 확대, 하루 장소 수 1곳 감소, 20시 이후 일정 제외, 도보 기준 거리 500m |
| 부모님 | 도보 구간 최소화, 도보 기준 거리 500m, 환승이 적은 경로 우선 |
| 이동 편의 토글 켜짐 (온보딩) | 동행과 관계없이 도보 기준 거리 500m, 환승이 적은 경로 우선. 아래 유모차·휠체어 규칙도 적용 (Notion 명세 대조 필요) |
| 그 외 | 도보 기준 거리 1km |

**접근성·반려동물** [제안]

DB의 `user_preferences`에는 유모차(`need_stroller`), 휠체어(`need_wheelchair`), 반려동물(`with_pet`) 값이 있습니다. 온보딩의 "이동 편의 토글"이 유모차·휠체어 값과 어떻게 연결되는지는 Notion 명세로 확인해야 합니다.

| 조건 | 장소 정보가 "가능" | "불가" | 정보 없음 |
|---|---|---|---|
| 유모차 필요 | 포함 | 제외 | 포함, 점수 감점, "유모차·휠체어 이용 정보 없음" 라벨 |
| 휠체어 필요 | 포함 | 제외 | 포함, 점수 감점, 같은 라벨 |
| 반려동물 동반 | 포함 | 제외 | 제외 (동반 불가로 간주) |

장소 정보는 TourAPI 소개 정보(유모차 대여, 반려동물 동반 정보, 무장애 정보)에서 가져옵니다.

**휴식 스타일**: 여행 스타일에 휴식이 있으면 체류 시간을 늘리고 장소 수를 줄입니다.

### 5.4 운영시간 [확정]

| 항목 | 규칙 | 상태 |
|---|---|---|
| 운영시간 미상 | 운영시간을 알 수 없는 장소도 코스에 넣을 수 있습니다. **"운영시간 확인 필요"** 라벨을 붙이고, 후보를 고를 때 점수를 조금 낮춥니다 | [확정] |
| 입장 마감 | 입장 마감 시각이 있으면 그 전에 도착하도록 짭니다. 떠나는 시각은 운영 종료 전이어야 합니다 | [신규] |
| 공휴일 | 여행 날짜가 공휴일(대체 공휴일 포함)이면 장소의 공휴일 규칙을 적용합니다. "공휴일 휴관", "정기 휴무일이 공휴일이면 다음 날 휴관"을 구분합니다. 규칙을 알 수 없으면 평일 규칙을 따릅니다 | [신규] |
| 축제 | 운영시간 대신 행사 시간과 행사 기간을 따릅니다. 기간 밖의 날에는 넣지 않습니다 | [신규] |

### 5.5 기본 추천 코스 [확정]

| 항목 | 규칙 |
|---|---|
| 언제 | AI 응답 지연, 오류, 형식 불일치, 보정할 수 없는 제약 위반 |
| 만드는 방식 | 후보 중 점수가 높은 장소를 출발지에서 가까운 순으로 페이스만큼 연결합니다. 운영시간과 식사 시간을 반영합니다 |
| 라벨 | "기본 추천 코스" |
| 추천 이유 | 템플릿 문장("인기 장소", "이전 장소에서 도보 8분" 등) |
| 횟수 | **차감하지 않습니다** [변경] (PRD v0.7은 "기본 코스까지 실패하면 차감 안 함") |
| 검증 | AI 코스와 같은 검증을 거칩니다. 위반이 남아도 경고 라벨을 달아 제공합니다 |
| 오류 | 인프라 장애(서버·DB 다운)일 때만 "잠시 후 다시 시도해 주세요"를 보여 주고 차감하지 않습니다 |

### 5.6 다시 추천 (FUNC-003-05)

| 항목 | 규칙 | 상태 |
|---|---|---|
| 조건 | 원래 요청의 조건을 그대로 씁니다. 원래 결과를 일차 수정(5.13)했어도 수정 내용은 반영하지 않습니다 | 기존 + [신규] |
| 사전 검사 | 생략합니다. 그사이 데이터가 바뀌어 생긴 문제(꼭 포함 장소의 휴무 등)는 결과의 경고로 알립니다 | [신규] |
| 다른 코스 | 원래 결과의 장소(꼭 포함 장소 제외)를 감점해 다른 장소가 나오게 합니다 | 기존 |
| 횟수 | AI 코스로 나오면 1회 차감, 기본 추천 코스로 나오면 차감하지 않습니다 | 기존 |
| 이전 결과로 | 직전 결과 1개로 돌아갈 수 있습니다. 직전 결과가 만료(24시간)됐으면 버튼을 숨깁니다 | 기존 + [신규] |
| 여행 상세에서 | 같은 여행의 새 일정안으로 저장할 수 있습니다. 이 화면에는 출발지가 없으므로 출발지 없이 짭니다 | 기존 + [신규] |

### 5.7 이동 수단 추천 (FUNC-003-03) [확정]
- **대중교통(도보 포함)이 기준**입니다. 자동차는 기준이 아닙니다.
- 도보 기준 거리(1km, 아이·부모님 동반 500m) 안이면 도보를 추천합니다.
- 그보다 멀면 대중교통 경로 후보 중 **소요 시간과 거리에 가중치를 둔 점수**가 가장 좋은 경로를 추천합니다(시간 0.7, 거리 0.3. 테스트로 조정).
- 대중교통 경로가 없을 때만 택시를 추천합니다. 택시 시간은 대안으로 함께 표시합니다(예: "추천: 대중교통 35분 · 택시 20분").
- 경로 조회에 실패하면 추정 시간에 **"예상 시간"** 라벨을 붙입니다.

### 5.8 식사 시간 확보 (FUNC-003-10)
- 점심 11:30–13:30, 저녁 17:30–19:30 안에 60분 "식사 시간" 슬롯을 넣습니다. 여행 시간대가 이 구간을 포함할 때만 넣습니다.
- 사용자가 음식점을 고르면 슬롯이 음식점으로 바뀌고, 이동 시간과 이후 시각을 다시 계산합니다(5.13 일차 수정). 운영시간을 넘는 장소가 생기면 경고를 표시합니다.
- 고르지 않은 슬롯은 저장과 캘린더 업로드에서 빠집니다.

### 5.9 식사·숙소 추천 목록 (FUNC-003-04, Spring 담당)
- 일차별 "이 근처 식사", "오늘 밤 숙소"를 최대 5개씩 보여 줍니다.
- 검색 반경은 식사 1km(식사 슬롯 앞뒤 장소 기준), 숙소 3km(그날 마지막 장소 기준)입니다. [제안]
- 당일 여행은 숙소를 보여 주지 않습니다.
- 숙소를 고르면 다음 날 출발점이 그 숙소로 바뀌고 다음 날 일정도 다시 계산합니다(5.3, 5.13).

### 5.12 결과 보관
- 추천 결과는 24시간 보관합니다. 지난 결과를 열면 "추천 결과가 만료됐어요. 다시 만들어 주세요"를 안내합니다.
- 일정안으로 저장한 코스는 보관 기간과 무관하게 유지됩니다.

### 5.13 일차 수정 [신규]

추천 결과를 일정안으로 저장하기 전에 일차 단위로 고칠 수 있습니다.

| 항목 | 규칙 |
|---|---|
| 할 수 있는 일 | 장소 삭제, 순서 변경, 체류 시간 변경, 식사 슬롯에 음식점 선택, 숙소 선택 |
| 재계산 | 고친 일차의 시각과 이동을 다시 계산합니다. 숙소를 고르면 다음 날도 다시 계산합니다 |
| 꼭 포함 장소 | 삭제할 수 있습니다. 사용자가 직접 뺀 것이므로 경고하지 않습니다 |
| 경고 | 고친 결과가 운영시간을 넘기면 `HOURS_CONFLICT`를 표시합니다. 막지는 않습니다 |
| 횟수 | 차감하지 않습니다 |
| 수정 가능한 결과 | AI 코스나 기본 추천 코스로 완료됐고 만료되지 않은 결과 |
| 동시 수정 | 같은 결과를 다른 탭에서 먼저 고쳤으면 "다른 곳에서 수정됐어요. 새로고침해 주세요"를 표시하고 저장하지 않습니다 |
| 개인화 | 삭제한 장소는 "AI 결과에서 삭제"(−3) 행동으로 기록합니다. 동의한 사용자만 기록합니다 |
| 원래 결과 | 처음 AI가 만든 결과는 따로 보관해 품질 측정(삭제율, 순서 변경률)에 씁니다 |

### 5.14 일정안으로 저장 [신규]

| 결과 항목 | 일정안 |
|---|---|
| 장소 | 일정 항목으로 저장합니다(장소, 일차, 순서, 도착·출발 시각, 체류 시간, 추천 이유) |
| 음식점을 고른 식사 슬롯 | 음식점 일정 항목으로 저장합니다 |
| 음식점을 고르지 않은 식사 슬롯 | 저장하지 않고 캘린더에도 올리지 않습니다 |
| 이동 | 다음 장소 항목에 이동 수단과 시간을 함께 저장합니다 |
| 라벨(운영시간 확인 필요, 예상 시간, 운영시간과 겹칠 수 있어요) | 해당 장소 항목에 함께 저장해 여행 상세에서도 보여 줍니다 |
| 기본 추천 코스 | 일정안에 출처로 표시합니다 |

저장은 횟수를 차감하지 않습니다.

## 6. 라벨과 경고

| 코드 | 화면 표시 | 붙는 조건 |
|---|---|---|
| `FALLBACK` | 기본 추천 코스 | AI 생성 실패로 기본 코스를 제공 |
| `HOURS_UNKNOWN` | 운영시간 확인 필요 | 운영시간을 알 수 없는 장소 |
| `ACCESS_UNKNOWN` | 유모차·휠체어 이용 정보 없음 | 유모차·휠체어가 필요한데 장소 정보가 없음(5.3) |
| `ROUTE_ESTIMATED` | 예상 시간 | 경로 조회 실패로 추정 시간을 표시 |
| `INDOOR_INSUFFICIENT` | 실내 장소가 부족해 실외 장소를 함께 넣었어요 | 실내 위주인데 실내 후보 부족 |
| `CANDIDATES_INSUFFICIENT` | 조건에 맞는 장소가 적어 일정이 짧아졌어요 | 후보가 필요한 수보다 적음 |
| `OVER_PACE` | 하루 일정이 많아요 | `allowOverPace`로 페이스를 넘김 |
| `HOURS_CONFLICT` | 운영시간과 겹칠 수 있어요 | 보정 후에도 운영시간 위반이 남음, 일차 수정 후 시간이 밀림 |
| `DEPARTURE_IGNORED` | 출발지에서 ○○까지 오는 시간은 일정에 포함되지 않아요 | 출발지가 멀거나 없음(5.3) |

## 7. 비기능 요구사항

| 항목 | 기준 |
|---|---|
| 응답 시간 | 사전 검사 1초 이내. 코스 생성 통상 12초, 최대 30초 |
